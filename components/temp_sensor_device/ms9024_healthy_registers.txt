MS9024 — Healthy Register Map (reference)
=========================================

Source     : Sensor at Modbus address 3 ("healthy" reference)
Captured   : Boot diagnostic scan (ms9024_diagnostic_scan), field-tests branch
Sensor cfg : PT100, 4-wire, Celsius output

Use this as the baseline when diffing against a suspect unit. The earlier
hardcoded repair values in ms9024_repair_from_good_unit (reg 27=0, 30=2,
129=282) came from a different source — note reg 129's actual healthy value
is 265 (0x0109), NOT 282 — so the repair function had at least one wrong
"good" value.

────────────────────────────────────────────
Suggested corrected "good_val" table for ms9024_repair_from_good_unit
────────────────────────────────────────────
Only the registers that differed between bad and good on the previously
investigated bad unit. If you re-enable the repair flow, use these values:

    {  26,  50, "FIN  (input filter)"          },   /* was 127 on bad unit */
    {  27,   0, "REG27 (offset/CJC related)"   },   /* was 200 on bad unit */
    {  30,   2, "REG30 (config param)"         },   /* was 0   on bad unit */
    { 129, 265, "REG129 (config/cal param)"    },   /* was 0   on bad unit; previously coded as 282 — WRONG */

Do NOT auto-run repair on a slave that just timed out — timeouts are not
evidence of register corruption. Trigger repair manually via
TEMP_SENSOR_REPAIR_FORM_GOOD_UNIT only when a sensor's full diagnostic dump
visibly diverges from this baseline.
