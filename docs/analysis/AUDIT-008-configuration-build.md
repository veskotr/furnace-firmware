# AUDIT-008 — Configuration and build map

**Scope:** source, build metadata, tracked `sdkconfig.defaults`, and ignored
local resolved `sdkconfig` only.
No target was flashed, booted, or connected to furnace hardware for this audit.

**Authority:** `CMakeLists.txt`, component `CMakeLists.txt`/`Kconfig` files,
`main/main.c`, tracked `sdkconfig.defaults`, and ignored local `sdkconfig` are the
evidence for this note.  A generated `sdkconfig` is a resolved result for a
specific ESP-IDF version and host environment, not a portable board record.

## Build entry points and baseline

| Item | Source-backed status |
| --- | --- |
| Project | Root `CMakeLists.txt` invokes ESP-IDF project `furnace-firmware`. |
| Application | `main/CMakeLists.txt` registers `main/main.c`; `app_main()` is the startup entry point. |
| Manifest | `main/idf_component.yml` requests ESP-IDF `>=4.1.0`, `joltwallet/littlefs ==1.20.4`, and `espressif/esp-modbus ^2.1.2`. |
| Locally resolved configuration | `sdkconfig` and `sdkconfig.defaults` are byte-identical, generated by ESP-IDF 5.5.4, target `esp32`, 2 MiB flash, DIO/40 MHz. |
| Known successful source build | The baseline record in `docs/codex/REPOSITORY_MAP.md` reports ESP-IDF 5.5.4 build success and a `0x63cb0` application image. This audit does not rerun that build. |

The manifest's broad ESP-IDF lower bound does not by itself demonstrate that
the tracked full resolved configuration can be regenerated or built with every
version from 4.1 onward.  The next clean build should therefore record the
exact ESP-IDF version and component-manager lock state used.

## Compiled graph and feature gates

The root build excludes `temperature_monitor_component`; its legacy
SPI/MAX31865 sources and Kconfig symbols remain in the repository but are not
in the production dependency graph.  `main` directly requires the active
Modbus/device/temperature path, heater/coordinator, dispatcher/event manager,
logger, fan, debug console, HMI, and related dependencies.

| Gate or state | Resolved value | Build/runtime consequence |
| --- | --- | --- |
| `CONFIG_NEXTION_HMI_ENABLED` | enabled | The Nextion component adds its coordinator, UART, UI, program, storage, and event source files; `app_main()` calls `nextion_hmi_init()`. |
| `CONFIG_RUN_INDICATOR_ENABLED` | disabled | The run-indicator is not a `main` dependency and is not initialized by current production startup. Its component remains retained for explicit test work. |
| health monitor | no Boolean gate | Component configuration is present and `main` requires it, but its `init_health_monitor()` call is commented out; it is not started by current startup. |
| PID adaptive output limit / feedforward | disabled / disabled | Their configuration exists, but the resolved build leaves both optional behaviors off. |
| legacy temperature monitor | root exclusion | `EXCLUDE_COMPONENTS temperature_monitor_component` prevents automatic production discovery/compilation. |

The active hardware-facing resolved defaults are: heater contactor GPIO 22,
SSR GPIO 21, fan GPIO 19, Modbus UART2 TX27/RX26/DE25 at 9600 baud, and Nextion
UART1 TX32/RX33 at 115200 baud.  This is a source configuration record only;
schematic wiring, output polarity, and electrical independence require bench
validation before operational reliance.

## Partition and persistent-storage mismatch — confirmed configuration gap

The resolved configuration selects `CONFIG_PARTITION_TABLE_SINGLE_APP=y` and
`CONFIG_PARTITION_TABLE_CUSTOM` is unset.  ESP-IDF therefore selects its
`partitions_singleapp.csv`: NVS, PHY data, and one 1 MiB factory application
partition.  The repository's `partitions.csv` is not selected.  It describes a
different, 8 MiB layout with a `storage` LittleFS partition.

This matters because `logger_init()` always calls `logger_init_storage()`, and
the latter registers LittleFS using the literal partition label `storage`.
That label is absent from the selected standard single-app table.  On a device
flashed from this resolved configuration, the source path reaches a failed
mount attempt; `logger_init()` logs the failure and continues.  This audit
does not claim the resulting serial log or filesystem behavior has been
observed on hardware.

The tracked 2 MiB flash setting is also incompatible with the end address of
the repository's unused `partitions.csv` (`0x800000`, 8 MiB).  The table cannot
be selected unchanged for the tracked flash-size setting.

**Improvement P-010 — establish one deployable partition/flash contract.**
Before a release build, choose the actual installed flash capacity and either:

1. select and right-size a custom table containing the required `storage`
   partition, or
2. remove/disable the logger's LittleFS dependency and its stale table.

Then perform a clean configure, inspect generated partition/flash arguments,
and boot-test mounting and crash-record persistence on representative hardware.

## Configuration provenance and source-list hygiene

`sdkconfig.defaults` is a complete generated resolved configuration (2,651
lines), identical to the local `sdkconfig`, rather than a small list of
intentional project overrides.  It pins many IDF defaults indirectly and makes
review of deliberate product choices difficult.  `sdkconfig.old` is local and
untracked.

Most component CMake files obtain `src/*.c` through plain `file(GLOB ...)`.
This is present in active components as well as legacy ones.  ESP-IDF/CMake
will not necessarily notice a newly added source until configuration is
rerun, so source-list changes are less self-evident in build metadata.  The
Nextion component instead uses an explicit source list and makes its HMI gate
visible at configure time.

**Improvement P-011 — separate intent from generated state.** Keep a concise,
reviewed `sdkconfig.defaults` (or documented profile defaults) and record the
toolchain/IDF version used to resolve it.  Regenerate `sdkconfig` in a clean
build rather than treating a locally generated file as the only build recipe.

**Improvement P-012 — standardize component source declaration.** Migrate
active components from plain source globs to explicit `SRCS` lists as a
behavior-preserving build-metadata change, with a clean reconfigure/build
check.  Do not combine it with functional changes.

## Audit conclusion

The current source maps one production-oriented resolved configuration, but it
does not yet provide a coherent deployable storage/partition contract.  The
partition mismatch is the first configuration item to resolve because it is
deterministically selected by the tracked build and directly affects an
always-initialized logger subsystem.  No physical safety claim is changed by
this documentation audit.
